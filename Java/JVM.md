# JVM(Java Virtual Machine) 정리

## 1. JVM이란?

**JVM(Java Virtual Machine)** 은 자바 바이트코드(`.class`)를 운영체제 위에서 실행해주는 가상 실행 환경입니다.

자바 프로그램은 보통 다음 흐름으로 실행됩니다.

```text
.java (소스코드)
→ javac 컴파일
→ .class (바이트코드)
→ JVM이 바이트코드 실행
```

즉, 자바는 **한 번 컴파일한 바이트코드를 JVM 위에서 실행**하기 때문에, 운영체제가 달라도 해당 환경에 맞는 JVM만 있으면 같은 프로그램을 실행할 수 있습니다.  
이것이 자바의 대표적인 특징인 **플랫폼 독립성(Write Once, Run Anywhere)** 의 핵심입니다.

---

## 2. JVM의 역할

JVM은 단순히 코드를 실행만 하는 것이 아니라, 다음과 같은 역할을 담당합니다.

- `.class` 파일을 읽고 메모리에 적재
- 필요한 클래스들을 동적으로 로딩
- 바이트코드를 해석하거나 기계어로 변환하여 실행
- 메모리 영역(Runtime Data Area) 관리
- 사용하지 않는 객체를 정리하는 가비지 컬렉션 수행
- 자바 코드와 네이티브 코드(C, C++ 등) 사이의 연결 지원

즉, JVM은 **자바 프로그램 실행에 필요한 전반적인 실행 환경을 제공하는 핵심 요소**입니다.

---

# 3. JVM의 구조

JVM은 크게 다음 구성 요소로 이루어집니다.

1. 클래스 로더(Class Loader)
2. 실행 엔진(Execution Engine)
3. 런타임 데이터 영역(Runtime Data Area)
4. JNI(Java Native Interface)
5. 네이티브 메서드 라이브러리(Native Method Library)

---

## 3-1. 클래스 로더(Class Loader)

클래스 로더는 `.class` 파일을 JVM 메모리로 읽어오는 역할을 담당합니다.  
자바는 필요한 클래스를 한 번에 모두 올리는 것이 아니라, **실행 도중 필요한 시점에 동적으로 로딩**합니다.

### 클래스 로더의 주요 역할

- `.class` 파일을 읽어서 JVM 메모리에 적재
- 클래스의 이름, 부모 클래스, 메서드, 필드 등의 정보를 분석
- 클래스 간 연결 작업 수행
- 클래스 초기화 진행

### 클래스 로딩 과정

클래스 로딩은 일반적으로 다음 3단계로 설명합니다.

#### 1) Loading
- 클래스 파일을 읽어와 JVM 메모리에 올림
- 클래스의 바이너리 데이터를 가져와 `Class` 객체 생성

#### 2) Linking
클래스를 사용할 수 있도록 검증하고 준비하는 단계입니다.

- **Verification**  
  바이트코드가 JVM 명세에 맞는지 검사  
  예: 잘못된 포맷, 보안 위반, 잘못된 상속 구조 확인

- **Preparation**  
  클래스 변수(static 변수)에 기본값 할당

- **Resolution**  
  클래스가 참조하는 다른 클래스나 메서드, 필드의 심볼릭 참조를 실제 참조로 변환

#### 3) Initialization
- `static` 변수에 실제 값 할당
- `static` 블록 실행

### 왜 동적 로딩이 중요한가?

자바는 필요한 클래스를 **실행 시점에 로드**하기 때문에 초기 로딩 부담을 줄일 수 있고,  
프레임워크나 서버 환경에서는 유연하게 클래스를 관리할 수 있습니다.

---

## 3-2. 실행 엔진(Execution Engine)

실행 엔진은 클래스 로더가 메모리에 적재한 **바이트코드**를 실제로 실행하는 역할을 합니다.

바이트코드는 사람이 바로 실행할 수 있는 기계어가 아니므로, JVM이 이를 해석하거나 변환해야 합니다.

실행 엔진의 주요 구성 요소는 다음과 같습니다.

- 인터프리터(Interpreter)
- JIT 컴파일러(Just-In-Time Compiler)
- 가비지 컬렉터(Garbage Collector)

---

### 1) 인터프리터(Interpreter)

인터프리터는 바이트코드를 **한 줄씩 읽고 해석하면서 바로 실행**합니다.

#### 장점
- 구현이 단순함
- 바로 실행 가능

#### 단점
- 같은 코드를 반복 실행할 때 매번 해석해야 하므로 느릴 수 있음

즉, 인터프리터는 빠르게 시작할 수 있지만, 반복 실행이 많은 구간에서는 성능 한계가 있습니다.

---

### 2) JIT 컴파일러(Just-In-Time Compiler)

JIT 컴파일러는 반복적으로 실행되는 바이트코드 영역을 찾아,  
그 부분을 **기계어로 컴파일해 캐시**해두는 방식입니다.

즉, 자주 실행되는 코드는 매번 해석하지 않고 이미 변환된 기계어를 사용하므로 성능이 향상됩니다.

#### 핵심 개념
- 처음에는 인터프리터 방식으로 실행
- 반복적으로 실행되는 코드가 발견되면 JIT가 해당 코드를 컴파일
- 이후에는 더 빠르게 실행

#### 장점
- 반복 실행되는 구간의 성능 향상
- 인터프리터의 단점을 보완

결국 JVM은 **인터프리터 + JIT 컴파일러를 함께 사용**하여 실행 초기 속도와 장기 성능을 모두 챙깁니다.

---

### 3) 가비지 컬렉터(GC)

가비지 컬렉터는 Heap 영역에 생성된 객체들 중에서 **더 이상 참조되지 않는 객체를 자동으로 제거**합니다.

C언어처럼 개발자가 직접 `free()`를 호출하는 방식이 아니므로,  
자바 개발자는 메모리 해제를 직접 처리하지 않아도 됩니다.

#### 장점
- 메모리 관리 부담 감소
- 메모리 누수 가능성 완화
- 생산성 향상

#### 주의할 점
- GC가 동작하는 동안 일시적으로 성능 영향을 줄 수 있음
- 무조건 “메모리 문제를 완전히 없애준다”기보다는, 자동 관리해주는 도구로 이해하는 것이 맞음

---

## 3-3. 런타임 데이터 영역(Runtime Data Area)

런타임 데이터 영역은 자바 프로그램이 실행될 때 JVM이 사용하는 메모리 공간입니다.  
이 영역은 **공유 영역**과 **스레드별 독립 영역**으로 나눌 수 있습니다.

---

### 1) 메서드 영역(Method Area)

메서드 영역은 클래스 수준의 정보가 저장되는 공간입니다.

주로 다음 정보들이 저장됩니다.

- 클래스 정보
- 인터페이스 정보
- 필드 정보
- 메서드 정보
- static 변수
- 런타임 상수 풀(Runtime Constant Pool)

#### 특징
- JVM 내에서 여러 스레드가 공유
- 클래스가 로드될 때 생성되는 정보 저장
- 클래스 단위의 메타데이터 보관

실무에서는 흔히 **“클래스 정보가 올라가는 영역”** 정도로 기억하면 좋습니다.

---

### 2) 힙 영역(Heap Area)

힙 영역은 **객체와 배열이 생성되는 공간**입니다.

예를 들어 아래와 같은 코드가 있다고 하면:

```java
Person p = new Person();
```

- `new Person()` 으로 생성된 객체는 **Heap** 에 저장
- 참조 변수 `p` 는 **Stack** 에 저장

#### 특징
- 모든 스레드가 공유
- 런타임 중 동적으로 메모리 할당
- GC의 주요 관리 대상

자바에서 가장 많이 메모리 관리 이슈가 발생하는 영역도 보통 Heap입니다.

---

### 3) 스택 영역(Stack Area)

스택 영역은 **메서드 호출 시 생성되는 프레임(Frame)** 을 저장하는 공간입니다.

여기에는 다음과 같은 정보가 저장됩니다.

- 지역 변수(Local Variable)
- 매개변수(Parameter)
- 연산 중 임시 데이터
- 메서드 호출 정보

메서드가 호출되면 스택에 프레임이 쌓이고, 메서드가 종료되면 프레임이 제거됩니다.

#### 특징
- 스레드마다 독립적으로 존재
- 메서드 호출과 함께 생성, 종료와 함께 제거
- 기본형 변수와 참조 변수 자체가 저장됨

#### 예시

```java
int a = 10;
Person p = new Person();
```

- `a` 값 자체는 Stack에 저장
- `p` 변수는 Stack에 저장
- 실제 `Person` 객체는 Heap에 저장

---

### 4) PC Register

PC Register는 현재 실행 중인 JVM 명령의 주소를 저장하는 공간입니다.

쉽게 말해, **“현재 어떤 명령어를 실행 중인지 가리키는 값”** 을 담고 있습니다.

#### 특징
- 스레드마다 하나씩 존재
- 멀티스레드 환경에서 각 스레드가 어디까지 실행했는지 구분 가능

---

### 5) 네이티브 메서드 스택(Native Method Stack)

자바가 아닌 **네이티브 코드(C, C++ 등)** 로 작성된 메서드를 실행할 때 사용하는 영역입니다.

예를 들어 JVM 내부 기능이나 OS 기능을 호출할 때 사용될 수 있습니다.

#### 특징
- 일반 자바 메서드 스택과는 별도
- 네이티브 메서드 실행을 위한 공간

---

## 3-4. JNI(Java Native Interface)

JNI는 자바 코드가 네이티브 언어(C, C++ 등)로 작성된 함수와 상호작용할 수 있도록 해주는 인터페이스입니다.

즉, 자바만으로 처리하기 어려운 OS 기능이나 하드웨어 제어, 기존 네이티브 라이브러리 활용이 필요할 때 JNI를 사용합니다.

### JNI가 필요한 이유
- 운영체제 고유 기능 사용
- 기존 C/C++ 라이브러리 재사용
- 성능상 네이티브 코드가 필요한 경우

---

## 3-5. 네이티브 메서드 라이브러리(Native Method Library)

네이티브 메서드 라이브러리는 C, C++ 등으로 작성된 실제 라이브러리 집합입니다.  
JNI를 통해 자바 프로그램과 연결됩니다.

예를 들어 운영체제 기능을 호출하거나, 저수준 시스템 자원을 다루는 경우 여기에 의존할 수 있습니다.

---

# 4. JVM 실행 과정

이제 JVM이 실제로 자바 프로그램을 어떻게 실행하는지 순서대로 정리해보겠습니다.

---

## 1단계. 자바 소스코드 작성

개발자는 `.java` 파일에 자바 소스코드를 작성합니다.

예:

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello Java");
    }
}
```

---

## 2단계. 컴파일

`javac` 컴파일러가 `.java` 파일을 **바이트코드(.class)** 로 변환합니다.

```text
Main.java
→ javac Main.java
→ Main.class
```

이 `.class` 파일은 운영체제에 종속적인 기계어가 아니라, JVM이 이해할 수 있는 중간 코드입니다.

---

## 3단계. JVM 시작 및 메모리 할당

자바 프로그램을 실행하면 JVM이 시작되고, 운영체제로부터 실행에 필요한 메모리를 할당받습니다.

이때 JVM은 다음과 같은 메모리 영역을 준비합니다.

- Method Area
- Heap
- Stack
- PC Register
- Native Method Stack

---

## 4단계. 클래스 로더가 클래스 로딩

JVM의 클래스 로더가 필요한 `.class` 파일을 읽어 메모리에 적재합니다.

이 과정에서 다음이 수행됩니다.

- Loading
- Linking
- Initialization

`main()` 메서드가 있는 클래스부터 시작해서,  
실행 중 필요한 다른 클래스들도 순차적으로 동적으로 로딩됩니다.

예를 들어 `System.out.println()` 을 사용하면 관련 클래스들도 함께 로딩됩니다.

---

## 5단계. 실행 엔진이 바이트코드 실행

클래스 로딩이 끝나면 실행 엔진이 바이트코드를 실행합니다.

처음에는 인터프리터 방식으로 한 줄씩 읽어 실행하고,  
반복적으로 호출되는 코드는 JIT 컴파일러가 기계어로 변환해 성능을 높입니다.

이 과정에서:

- 메서드 호출 시 Stack 프레임 생성
- 객체 생성 시 Heap 메모리 사용
- 클래스 정보는 Method Area에 저장
- 각 스레드는 PC Register로 현재 명령 위치 관리

---

## 6단계. 가비지 컬렉션 수행

프로그램 실행 중 Heap에 생성된 객체 중 더 이상 참조되지 않는 객체는 GC가 정리합니다.

예를 들어 어떤 객체를 참조하던 변수가 사라지거나 `null` 이 되어 더 이상 접근할 수 없으면,  
GC의 대상이 될 수 있습니다.

---

## 7단계. 프로그램 종료

프로그램 실행이 끝나면 JVM도 종료되고, JVM이 사용하던 메모리 역시 운영체제에 반환됩니다.

---

# 5. 전체 흐름 한눈에 보기

```text
1. 개발자가 .java 파일 작성
2. javac가 .java를 .class(바이트코드)로 컴파일
3. JVM 실행
4. 클래스 로더가 .class 파일 로딩 및 링크
5. 런타임 데이터 영역에 필요한 데이터 적재
6. 실행 엔진이 바이트코드 실행
   - 인터프리터가 우선 실행
   - 반복 코드는 JIT 컴파일러가 최적화
7. Heap의 불필요한 객체는 GC가 정리
8. 프로그램 종료
```

---

# 6. 면접에서 말하기 좋은 핵심 정리

## JVM 한 줄 설명
**JVM은 자바 바이트코드를 운영체제에 맞게 실행해주는 가상 머신입니다.**

## JVM의 핵심 역할
- 클래스 로딩
- 바이트코드 실행
- 메모리 관리
- 가비지 컬렉션
- 네이티브 코드 연동 지원

## JVM 메모리 구조 핵심
- **Method Area**: 클래스 정보, static 변수, 상수
- **Heap**: 객체, 배열
- **Stack**: 지역 변수, 매개변수, 메서드 호출 정보
- **PC Register**: 현재 실행 중인 명령 위치
- **Native Method Stack**: 네이티브 메서드 실행 영역

## 실행 엔진 핵심
- **Interpreter**: 바이트코드를 한 줄씩 해석
- **JIT Compiler**: 자주 실행되는 코드를 기계어로 변환
- **GC**: 사용하지 않는 객체를 자동 회수

---

# 7. 자주 헷갈리는 포인트 정리

## 1) Stack에는 무엇이 저장되나요?
- 기본형 변수의 값
- 참조 변수 자체
- 메서드 호출 정보

## 2) Heap에는 무엇이 저장되나요?
- `new` 로 생성된 객체
- 배열

## 3) 참조 변수와 객체는 어디에 저장되나요?
예:

```java
Person p = new Person();
```

- `p` → Stack
- `new Person()` 객체 → Heap

## 4) JVM과 JDK, JRE 차이
- **JVM**: 자바 프로그램을 실행하는 가상 머신
- **JRE**: JVM + 자바 실행에 필요한 라이브러리
- **JDK**: JRE + 개발 도구(`javac` 등)

# 8. 마무리

JVM은 자바의 핵심 실행 환경으로,  
자바 프로그램이 운영체제에 종속되지 않고 실행될 수 있도록 도와줍니다.

또한 클래스 로딩, 메모리 관리, 실행 최적화, 가비지 컬렉션 등  
프로그램 실행에 필요한 대부분의 기능을 담당합니다.

그래서 JVM을 이해하면 단순히 “자바가 실행된다”를 넘어,

- 객체가 어디에 저장되는지
- 메서드 호출이 어떻게 동작하는지
- 왜 GC가 필요한지
- 왜 자바가 운영체제 독립적인지

까지 함께 이해할 수 있습니다.

---

## 9. 면접용 마무리 답변 예시

> JVM은 자바 바이트코드를 실행하기 위한 가상 머신입니다.  
> 클래스 로더가 `.class` 파일을 메모리에 올리고, 실행 엔진이 이를 해석하거나 JIT 컴파일하여 실행합니다.  
> 이 과정에서 Method Area, Heap, Stack 같은 런타임 메모리 영역을 사용하고, Heap의 불필요한 객체는 GC가 자동으로 회수합니다.  
> 그래서 자바는 운영체제와 독립적으로 실행될 수 있고, 개발자는 비교적 편리하게 메모리를 관리할 수 있습니다.
